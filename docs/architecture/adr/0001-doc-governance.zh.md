# ADR-0001: 架构文档治理基线

状态: Accepted
日期: 2026-03-04

## 背景（Context）
当前仓库缺少长期可演进的架构文档治理机制，导致接口、流程与实现容易出现描述漂移。

## 决策（Decision）
采用 `docs/architecture/` 作为唯一架构文档根目录，并强制以下规则：
- 架构级变更必须同步更新总览与对应分层文档。
- 重大决策必须新增 ADR。
- 每次架构变更必须登记 `changelog.md`。

## 备选方案（Alternatives）
1. 只维护单文件总览。
- 优点：维护成本低。
- 缺点：信息堆叠，难以长期扩展。

2. 仅在 PR 描述中记录架构变化。
- 优点：无需额外文档。
- 缺点：知识分散，不可持续追踪。

## 影响（Consequences）
- 正向影响：文档可演进、可追溯、可联调。
- 负向影响：每次架构改动增加文档维护成本。

## 回滚策略（Rollback）
若治理成本过高，可回退到“总览 + changelog”最小模式，并将 ADR 降级为可选。
